Important: Overlay tools ARE NOT ACCESSIBILITY SOLUTIONS!

This tool provides a simple way to adjust some reading preferences. Many of its settings are also available through browsers, operating systems, and assistive technologies. Offering them directly on a site may be convenient for some people, but it does not replace the fixes needed to make content and functionality accessible. These are different things.

02 / HOW TO INSTALL

Just one line to start the “miracles”

The previous sentence is ironic. There is nothing miraculous about offering settings that people already have for free in their operating systems.

  1. Download and extract the files.

    Download the tool as a ZIP . Extract the package and upload the folder a11y-preferences to your site's root directory, keeping the subfolders css , js and fonts .

  2. Add this line to the <head>. 
    <script src="/a11y-preferences/js/preferences.js" defer></script>

    The JavaScript loads the CSS automatically. If your site is in a subfolder, adjust the path.

  3. Test it on your pages.

    Check combinations of preferences, keyboard use, and small screens. Results depend on your site's HTML and CSS.

This project aims to show how simple it is to implement a tool like this and that nobody needs to pay for one. Remember, though, that this kind of tool does not remove accessibility barriers! This project is open source. Visit GitHub (opens in a new tab) and use it as you wish.

03 / NO MIRACLE PROMISES

Adjusting the experience does not mean removing accessibility barriers.

This tool lets you personalize how content is presented. That may be useful, but it does not mean a site has become accessible. Before implementing features like these, consider a few questions.

Before implementing any adjustment tool, ask yourself the following questions

1. If the problems are in the code and content, why try to solve them by changing their appearance?

Images without descriptions, buttons without accessible names, unlabeled forms, and components that cannot be operated with a keyboard are examples of barriers that do not disappear when you enlarge text, change colors, or highlight elements.

2. Are we offering new possibilities or trying to compensate for problems that should have been fixed?

Preferences can improve the experience for some people. But they should not justify leaving known barriers in place. Before adding features, make sure the existing functionality can be used.

3. If people already have their own preferences and assistive technologies, are we respecting those choices?

Browsers, operating systems, and assistive technologies already offer many personalization features. An additional tool should respect those settings, offer choices, and avoid interfering with people's experience.

4. Consider: Why do the websites of major technology companies such as Apple, Google, and Microsoft not use this kind of feature, yet remain fully accessible?

The sales pitch for overlay tools is persuasive, but these tools are not important for removing accessibility barriers and generally only slow your site down. If you still consider features like these relevant, look for ways to implement them without spending money on them. Prefer investing your budget in training the teams involved in developing your websites and apps.

5. Remember: The number of features is NOT a measure of accessibility

It does not matter how many features are offered when most of them are already available to the people who need them. Some examples:

  • People with color vision deficiencies adjust colors in their own operating systems, so providing additional features for this is not relevant.
  • There are different ways to enlarge content, through a keyboard or browser settings. People who need magnification already do this naturally.
  • All operating systems offer options to enlarge mouse pointers or change their colors, so a specific feature for this is unnecessary.

Adjustment tools are complementary. Do not use them as a solution to accessibility problems.

04 / AVAILABLE FEATURES

Here is the list of features and functions available here

It is worth repeating that these features duplicate functions that already exist. That said, these are the available features and functions:

Available features and options
Feature Available options
Content zoom Original, 125%, 150%, 175%, 200%, 300%, and 400%.
Color and contrast Original, black on white, white on black, yellow on black, and sepia.
Highlight controls Outlines and a minimum height for fields and buttons; underlining and bold text for links.
Font style Original, system font, serif, Arial, Atkinson Hyperlegible, Lexend, Open Sans, and Verdana.
Bold Can be enabled independently of the selected font.
Text size Original, 125%, 150%, 175%, and 200%.
Line spacing Original, 1.5, 1.75, and 2.
Letter spacing Original, 0.05, 0.10, and 0.15 em.
Word spacing Original, 0.10, 0.20, and 0.30 em.
Pause animations Pauses supported animations and HTML videos, and disables transitions.
Mute sounds Mutes HTML audio and video elements that the tool can access.

Available functions:

  • Floating mode: move the panel by dragging, using arrow keys, or using direction buttons, with position information for screen readers.
  • Expandable groups: open groups individually or show all preferences.
  • Compact trigger: replace the button text with an icon.
  • Hide the trigger: choose not to display the button on that page.
  • Automatic saving: preferences stored locally in the browser, per site.
  • Restore defaults: remove adjustments and return to the original presentation.
  • Keyboard operation: close with Escape and manage focus when opening and closing.
