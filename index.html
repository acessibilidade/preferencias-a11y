Essa é uma ferramenta que permite ajustar algumas preferências de leitura de conteúdo de forma simples. Diversos ajustes disponíveis nesta ferramenta também podem ser realizados por meio de recursos dos navegadores, sistemas operacionais e tecnologias assistivas. Oferecê-los diretamente em um site pode ser conveniente para algumas pessoas, mas não substitui as correções necessárias para tornar conteúdos e funcionalidades acessíveis. São coisas distintas.

02 / COMO INSTALAR

Basta uma linha para começar os "milagres"

A frase anterior contém ironia. Não há milagres em oferecer configurações que as pessoas já possuem de forma gratuita em seu próprio sistema operacional.

  1. Baixe e extraia os arquivos.

    Baixar a ferramenta em ZIP . Extraia o pacote e envie a pasta ferramentas para a raiz do seu site, preservando as subpastas css , js , fonts e img .

  2. Inclua esta linha no <head>. 
    <script src="/ferramentas/js/preferencias.js" defer></script>

    O JavaScript carrega o CSS automaticamente. Se o site estiver em uma subpasta, ajuste o endereço.

  3. Teste nas suas páginas.

    Confira as combinações de preferências, teclado e telas pequenas. O resultado depende do HTML e do CSS do seu site.

Este projeto tem o intuito de demonstrar como implementar uma ferramenta como essa é verdadeiramente simples e ninguém precisa pagar por elas, mas lembre-se que esse tipo de ferramenta não remove barreiras de acessibilidade! Este projeto tem o código aberto, acesse o GitHub (abre em uma nova aba) e use como quiser.

03 / SEM PROMESSAS MILAGROSAS

Ajustar a experiência não significa remover barreiras de acessibilidade.

Esta ferramenta permite personalizar a apresentação de conteúdos. Isso pode ser útil, mas não significa que um site se tornou acessível. Antes de implementar recursos como esses, vale refletir sobre algumas questões.

Antes de implementar qualquer tipo de ferramenta de ajustes, faça os seguintes questionamentos

1. Se os problemas estão no código e no conteúdo, por que tentar resolvê-los mudando a aparência?

Imagens sem descrição, botões sem nomes acessíveis, formulários sem rótulos e componentes que não funcionam com teclado são exemplos de barreiras que não desaparecem ao aumentar textos, alterar cores ou destacar elementos.

2. Estamos oferecendo novas possibilidades ou tentando compensar problemas que deveriam ter sido corrigidos?

Preferências podem melhorar a experiência de algumas pessoas. Mas não deveriam ser utilizadas como justificativa para manter barreiras conhecidas. Antes de adicionar recursos, é preciso garantir que as funcionalidades existentes possam ser utilizadas.

3. Se as pessoas já possuem suas próprias preferências e tecnologias assistivas, estamos respeitando essas escolhas?

Navegadores, sistemas operacionais e tecnologias assistivas já oferecem diversos recursos de personalização. Uma ferramenta adicional deve respeitar essas configurações, permitir escolhas e evitar interferências na experiência das pessoas.

4. Reflita: Por que os sites das grandes empresas de tecnologia, como Apple, Google ou Microsoft não usam esse tipo de recurso, mas ainda assim são perfeitamente acessíveis?

Não caia no conto de vendedores de ferramentas do tipo "overlay", elas não são importantes para eliminar barreiras de acessibilidade e geralmente apenas diminuem a performance de seu site. Mas se mesmo assim achar relevantes a implementação de recursos como estes, procure por diferentes formas de implementação sem investir recursos financeiros para isso. Prefira investir seu orçamento na capacitação das equipes envolvidas no desenvolvimento de seus sites e aplicativos.

Ferramentas de ajustes são complementares. Acessibilidade precisa fazer parte do produto.
